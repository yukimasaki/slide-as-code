# slide-as-code

話しながら映すスライドを作る。配色、フォント、動き、場面の演出は、話の中身に合わせて決める。

## 進め方

1. **材料を集める。** 発表の対象、持ち時間、話したあとに相手に何を決めてほしいかを確認する。自分で調べて分かることは聞かない。数字と事実の出典を集め、出典のない数字は使わない。
2. **構成を表にする。** 列は「ページ・見出し・中身」。5分なら7枚ほどを目安に、1枚で1つのことを伝える。ユーザーが構成を指定していなければ、構成への合意を得てから作る。
3. **出力先を決め、HTMLを作る。** 下の「出力先」のヘルパーを実行し、表示されたパスに書き出す。
4. **確認する。** 下の「確認の関門」に従い、確認した項目と未確認の項目を記録する。
5. **報告する。** 出力したHTMLの絶対パス、ブラウザでの開き方、確認結果を報告して完了する。修正の依頼では、対象のHTMLを更新して同じ項目を報告する。

## 出力先

このスキルのディレクトリを基準に `scripts/output_path.py` を実行する。カレントディレクトリがリポジトリのルートなら、次のように実行できる。

```bash
python3 skills/slide-as-code/scripts/output_path.py --name example-talk
```

ヘルパーは資料のディレクトリを作り、`index.html` の絶対パスを表示する。そのパスにHTMLを書き出す。HTMLの生成や既存ファイルの上書きはヘルパー自身は行わない。

- 既定の出力先: `${XDG_DATA_HOME:-~/.local/share}/slide-as-code/<資料名>/index.html`
- 設定ファイル: `${XDG_CONFIG_HOME:-~/.config}/slide-as-code/config.json`
- 設定キー: `outputDir`。資料のディレクトリを置く親ディレクトリを指定する。

```json
{
  "outputDir": "~/Documents/slides"
}
```

パス先頭の `~` はホームディレクトリに展開する。絶対パスも使える。相対パスや `$変数名` の展開には対応しない。XDG環境変数は未設定または空なら既定値を使い、設定する場合は絶対パスにする。設定ファイルや `outputDir` がなければ既定の出力先を使う。不正な設定はエラーを直してから進める。

ヘルパーはシンボリックリンクを解決し、Gitリポジトリ内の保存先を拒否する。資料名は1つのディレクトリ名とし、パス区切りや `.`・`..` を含めない。成果物をスキルのリポジトリに置いたり、資料の一覧を追記してコミットしたりしない。

## 事実の忠実さ

- 数字には出典と確認日を添える。
- 出典から計算した比、合計、換算は、計算のもとを本文か注に書く。為替の換算では、使ったレートも書く。
- 比較表の○・△・×などを自分で判定する場合は、根拠を記録し、話す人が確かめられるようにする。
- 推測と確認済みの事実を分ける。未確認のことは未確認と書く。

## 文章の調子

- 身近でやさしい言い回しを使い、見出しを短くする。ユーザーの指定した語彙や文体を優先する。
- 1枚の文字を少なくし、話す人が口で補える量にする。

## 技術の決まり

ブラウザで単独で開けるように、1つのHTMLファイルに必要なものを埋め込む。

- CSS、JavaScript、画像をHTML内に入れる。SVGはインラインかdata URIにする。CDNのJavaScript、外部フォント、外の画像を読み込まない。
- `localStorage`、`sessionStorage`、`indexedDB`、`document.cookie` に依存しない。ページの状態はメモリ内で管理する。
- `/x.png` のようなルートからの絶対パスを使わない。
- フォントはシステムのものを使う。例: `"Hiragino Sans", "Noto Sans JP", "Yu Gothic UI", sans-serif`。

スライドの形:

- 舞台を1600×900などの固定サイズで組み、画面に合わせて縮める。舞台は `position: absolute; left: 50%; top: 50%` に置き、`transform-origin: center` と `translate(-50%, -50%) scale(k)` で中央に合わせる。
- キー（←・→・Space・PageUp・PageDown）、クリック、スワイプでページをめくれるようにする。下に今の位置（3 / 7など）を出す。
- 動きで意味を伝える。流れを順に見せる、数字をカウントアップする、差を棒の長さで示す、といった使い方をする。
- `prefers-reduced-motion` では動きを止め、最終状態を表示する。

## 確認の関門

- 外部ファイルの読み込みや保存機能の使用を検査する。次の検索結果は候補として読み、出典へのリンクやSVGの名前空間と、実際の外部読み込みを区別する。
  ```bash
  rg -n 'https?://|<script[^>]+src|<link[^>]+href|localStorage|sessionStorage|indexedDB|document\.cookie' '<出力先>/index.html'
  ```
- ユーザーが指定した公開範囲に合わせて内容を点検する。秘密情報や関係のない個人情報が入っていないか確認する。
- 全ページの最終状態を目で見る。文字の欠け、はみ出し、重なり、操作ボタンとの重なりを、1920×1080ほどの画面と幅700pxほどの狭い画面で確認する。
- ブラウザの操作は、その環境の指示とユーザーの許可範囲に従う。表示を確認できない場合は、未確認であることと、ユーザーに見てほしい項目を報告する。
- 見た目を直したら全ページを見直す。

## 表示で注意すること

- 画面より大きい舞台をgridやflexの中央寄せに頼って置くと、狭い枠で縮小したあとに位置がずれることがある。舞台の位置と変形を上の方法で指定する。
- 表や結びの文章が操作ボタンと重ならないように、行の高さを足し、舞台の高さから上下の余白を引いた範囲に収める。
- 静的な検査だけでは、文字の欠けや重なりを確認できない。ブラウザで確認できなかった場合、表示の確認を済ませたと報告しない。

## 完了の報告

HTMLの絶対パスと、ファイルマネージャーまたはブラウザの「ファイルを開く」から開けることを伝える。必要なら `file://` URLも添える。ユーザーへの報告には、確認結果と未確認の項目を含める。
